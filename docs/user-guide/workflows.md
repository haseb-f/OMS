# مسارات العمل والمراحل

مرجع عملي مبني على DEMO-GUIDE-20260924. العملة: **EGP**.

## قاعدة حرجة: الدفع ≠ الشحن

| المحور               | يصف                      | لا يعني                |
| -------------------- | ------------------------ | ---------------------- |
| حالة الدفع / التسوية | هل المبلغ محصّل ومُرحّل؟ | أن الطلب خرج مع الناقل |
| حالة الشحن / التنفيذ | هل شُحن أو سُلّم؟        | أن العميل دفع          |

**مثال موثّق:** [STO-2026-000083](https://oms.haseb.org/store-orders/e5cf5e89-c276-49b4-9f13-ce969fa6cafa)

- الإجمالي 900، المدفوع 900، المتبقي 0
- `paymentStatus = FULLY_PAID_RECONCILED`، الدفع VERIFIED
- فاتورة INV-2026-000057 = PAID
- قيود: JV-2026-000235 (قبض) + JV-2026-000236 (فاتورة)
- **جاهز للشحن / لم يُشحن** في سيناريو الجولة

**مثال شحن مكتمل:** STO-2026-000084 — بعد ship → out-for-delivery → deliver أصبحت الشحنة DELIVERED مع تكلفة شحن 30.

## 1) مسار متجر (Lead → STO → دفع → فاتورة)

| المرحلة         | المالك       | أثر لاحق                                                |
| --------------- | ------------ | ------------------------------------------------------- |
| عميل محتمل NEW  | مبيعات       | لا قيد                                                  |
| تحويل بمبلغ > 0 | مبيعات       | إنشاء عميل + طلب متجر                                   |
| تحويل بمبلغ 0   | —            | **مرفوض**؛ يبقى عميلاً محتملاً                          |
| تسجيل دفع       | مبيعات/مالية | مسودة/انتظار تأكيد                                      |
| Confirm & Post  | مالية/مخوّل  | VERIFIED + سند قبض + قيد؛ التكرار → `alreadyPosted`     |
| طلب مسدَّد      | نظام         | يرفض دفعة إضافية                                        |
| توليد فاتورة    | مخوّل فاتورة | قيد فاتورة + حركة مخزون مبيعات عند الترحيل؛ منع التكرار |
| جاهز للشحن      | تشغيل        | لا يغيّر حالة الدفع تلقائياً لـ «مشحون»                 |

## 2) مسار الشحن بعد الفاتورة/الدفع

| المرحلة          | المالك | أثر                                                         |
| ---------------- | ------ | ----------------------------------------------------------- |
| تسجيل تكلفة شحن  | شحن    | تُثبت مع التسليم كقيد                                       |
| SHIPPED          | شحن    | تحديث حالة الشحنة                                           |
| OUT_FOR_DELIVERY | شحن    | تحديث حالة الشحنة                                           |
| DELIVERED        | شحن    | قيد SHIPMENT_COST مرة واحدة (idempotent عند إعادة المحاولة) |

## 3) مرتجع بعد التسليم → استرداد نقدي (إن لزم)

| المرحلة                        | المالك                          | أثر                                                                                               |
| ------------------------------ | ------------------------------- | ------------------------------------------------------------------------------------------------- |
| تسليم ثم مرتجع بكمية صحيحة     | مبيعات                          | قيد عكس + مخزون راجع؛ رصيد دائن عميل بمبلغ المرتجع                                                |
| كمية أكبر من القابل للإرجاع    | —                               | **مرفوض**                                                                                         |
| إعادة تأكيد المرتجع            | —                               | لا قيد جديد                                                                                       |
| رد مبلغ نقدي (Customer Refund) | مالية / مخوّل `sales.refunds.*` | صرف النقد؛ قيد يومية للرد؛ يقلّل الرصيد الدائن                                                    |
| بعد رد كامل                    | نظام                            | `refundableAmount = 0` وغالباً `customerCreditBalance = 0`؛ كشف العميل يغلق على **0** لهذا المسار |

**مسار موثّق:** مرتجع → رد نقدي مؤكد → قيد JE → كشف يغلق على 0.

| مثال                | التفاصيل                                                                               |
| ------------------- | -------------------------------------------------------------------------------------- |
| مرتجع ثم رد         | SR-2026-000015 (450) → CRF-2026-000002 (CONFIRMED 450) → رصيد قابل للرد/دائن = 0       |
| رد سابق             | CRF-2026-000001 (CONFIRMED 450) ضد SR-2026-000014                                      |
| رد من الواجهة (GAP) | SR-2026-000016 (200) → CRF-2026-000003 + JV-2026-000270 → refundable=0 · كشف closing=0 |
| جاهز لحوار UI       | SR-2026-000016 — refundable **200** (DEMO-GUIDE-GAP-20260924)                          |

**واجهة:** من مرتجع المبيعات إجراء **«رد مبلغ»** · قائمة الردود `/sales/payments?view=refunds` · تفاصيل `/sales/refunds/:id`.  
**API:** `/financial-transactions/refunds` (+ `/confirmed`، `/refundable/:id`).

مرجع مرتجع F2: STO-2026-000085 / SR-2026-000015 / JV-2026-000242.  
تصحيح ادعاء «لا API»: [evidence/VERSION-REFUND-RESOLUTION.md](./evidence/VERSION-REFUND-RESOLUTION.md).

> **الدفع ≠ الشحن** يبقى كما في القسم أعلاه — الاسترداد النقدي يغلق الذمة/الرصيد الدائن ولا يغيّر حالة الشحنة.

## 4) مسار B2B (عرض → أمر → فاتورة → قبض)

| المرحلة      | أثر                                     |
| ------------ | --------------------------------------- |
| عرض APPROVED | لا تحصيل بعد                            |
| أمر مؤكد     | التزام تشغيلي                           |
| فاتورة مؤكدة | قيد + COGS                              |
| قبض جزئي     | PARTIALLY_PAID                          |
| قبض مكمّل    | PAID، كشف يغلق على 0 (قبل عمليات لاحقة) |

مرجع: SO-2026-000012 / INV-2026-000060 / CR-2026-000042 (600) + CR-2026-000043 (900).

## 5) مسار المشتريات

| المرحلة            | أثر                             |
| ------------------ | ------------------------------- |
| عرض → أمر APPROVED | التزام شراء                     |
| فاتورة مؤكدة       | Dr مخزون / Cr ذمم + استلام كمية |
| دفع جزئي/كامل      | PARTIALLY_PAID → PAID           |
| مرتجع شراء         | يقلل المخزون ويحرّك ذمم المورد  |

مرجع: PO-2026-000004 / PI-2026-000032 / PR-2026-000008.

## 6) مخزون ومتوسط متحرك (ملخص F5)

- افتتاحي + مشتريات يحدّثان `currentCost` (مثال Book Lab → 33).
- البيع يستهلك COGS = كمية × المتوسط.
- onHand لصنف التجارب = 16 بعد الجولة.

## 7) قيود اليومية

| النوع                    | التعديل بعد الترحيل                                                  |
| ------------------------ | -------------------------------------------------------------------- |
| قيد يدوي                 | مسودة قابلة للتعديل؛ مرحّل يمكن إعادته لمسودة ثم إعادة ترحيل (موثّق) |
| قيد نظامي (فاتورة/قبض/…) | **ممنوع** التعديل أو الإعادة لمسودة — صحّح المستند المصدر            |

## مسرد حالات (مختصر)

| المصطلح                                | المعنى العملي                           |
| -------------------------------------- | --------------------------------------- |
| NEW (عميل محتمل)                       | لم يُحوَّل                              |
| VERIFIED (دفع متجر)                    | مؤكد ومُرحّل                            |
| FULLY_PAID_RECONCILED                  | مسدَّد ومسوّى — لا دفعة إضافية          |
| PARTIALLY_PAID                         | دُفع جزء                                |
| PAID (فاتورة)                          | لا متبقي على الفاتورة                   |
| DRAFT (فاتورة/قيد)                     | غير مرحّل                               |
| POSTED                                 | مرحّل محاسبياً                          |
| CONFIRMED (مرتجع / رد CRF)             | مؤكد؛ للرد يعني صُرف النقد ورُحّل الأثر |
| refundableAmount                       | المتبقي القابل لرد نقدي على المرتجع     |
| customerCreditBalance                  | رصيد دائن العميل المتاح للرد            |
| SHIPPED / OUT_FOR_DELIVERY / DELIVERED | مراحل الشحنة                            |
| alreadyPosted                          | تأكيد مكرر دون أثر محاسبي جديد          |
| APPROVED (عرض/أمر شراء)                | معتمد للمرحلة التالية                   |
