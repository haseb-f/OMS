# الشحن (Shipping)

حساب التحقق: `qa-shipping@oms.haseb.org`

صلاحيات السكربت: `store-orders.view`، `shipping.view`، `shipping.edit`، `shipping.print`، `shipping.export`.

## التبويبات المستخدمة

- الشحن: مكتب الشحن (`/shipping`)، استيراد الشحن، حالات الشحن، شركات الشحن
- طلبات المتجر (عرض) لمتابعة الطلب المرتبط

لا يظهر له عادةً CRM أو المالية أو المشتريات.

## مهام شائعة

### 1) شحن طلب مدفوع حتى التسليم

1. افتح مكتب الشحن أو الطلب من طلبات المتجر.
2. سجّل تكلفة الشحن إن لزم (مثال DEMO: 30 EGP).
3. نفّذ التسلسل الموثّق: شحن → خرج للتسليم → تم التسليم.
4. عند التسليم يُترحَّل قيد تكلفة الشحن مرة واحدة؛ إعادة التسليم لا تُضاعف القيد.

مرجع: [STO-2026-000084](https://oms.haseb.org/store-orders/5fc98c37-6071-429d-818d-606b97d7aa96) — إجمالي 450، شحن 30، COGS 40، الحالة DELIVERED، قيد [JV-2026-000239](https://oms.haseb.org/finance/journal-entries/5b3d187b-ac5f-4e20-b715-3615731f919d).

### 2) طلب مدفوع وجاهز للشحن ولم يُشحن بعد

1. ابحث عن الطلبات الجاهزة دون شحن.
2. مثال موثّق من السيناريو: STO-2026-000083 — مدفوع بالكامل (`FULLY_PAID_RECONCILED`) وجاهز للشحن **ولم يُشحن**.
3. لا تنتظر «إعادة الدفع» — الدفع منفصل عن الشحن.

### 3) استيراد تحديثات الشحن

1. الشحن → استيراد.
2. الصفحة تُحمَّل (مسح المتصفح HTTP 200).
3. سيناريوهات الاستيراد التفصيلية **NOT TESTED** في جولة بيانات DEMO-GUIDE.

## المراحل ومن المسؤول (شحن)

| الخطوة (API/جولة) | الحالة بعد النجاح                      |
| ----------------- | -------------------------------------- |
| ship              | SHIPPED                                |
| out-for-delivery  | OUT_FOR_DELIVERY                       |
| deliver           | DELIVERED (+ قيد تكلفة الشحن إن وُجدت) |

المبيعات/المالية تسبق عادةً بإغلاق الدفع والفاتورة؛ الشحن يملك حركة الناقل فقط.

## الدفع مقابل الشحن (حرج)

|              | الدفع                   | الشحن                           |
| ------------ | ----------------------- | ------------------------------- |
| معنى         | هل حُصّل المبلغ ورُحّل؟ | هل خرج الطلب مع الناقل / سُلّم؟ |
| مثال STO-083 | مدفوع بالكامل           | لم يُشحن بعد (جاهز)             |
| مثال STO-084 | مدفوع                   | DELIVERED                       |

لا تستخدم حالة الدفع كبديل لحالة الشحن في التقارير التشغيلية.

## أخطاء شائعة

- افتراض أن «مدفوع» = «تم التسليم».
- محاولة إنشاء تكلفة شحن/تسليم مكررة — النظام يحافظ على قيد واحد لتكلفة الشحن عند إعادة المحاولة (موثّق).
- تعديل حالات الشحن الأساسية دون تنسيق مع البيانات الأساسية قد يفسد التدفق — غيّر الحالات بحذر (صفحة الحالات تُحمَّل؛ تعديلها **غير مختبر** في F2 الذي استخدم مسارات API القياسية).

## تقارير ذات صلة

- `/reports/shipping` = **قشرة «قريباً»**.
- تتبع المستندات من الطلب (فاتورة، دفعات، شحنات، حركات مخزون) موثّق في F2/F6 عبر API التتبع.
