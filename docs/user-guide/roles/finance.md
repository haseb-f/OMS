# المالية (Finance)

حساب التحقق: `qa-finance@oms.haseb.org`

صلاحيات السكربت تشمل: عرض المالية، دليل الحسابات، قيود اليومية، سنوات مالية، قبض عملاء (عرض/إنشاء/تعديل/تأكيد)، **ردود نقدية عملاء `sales.refunds.*`** (عرض/إنشاء/تعديل/تأكيد/طباعة)، مدفوعات موردين، مدفوعات مصروف، تقارير مالية (عرض/طباعة/تصدير)، تحليل تكلفة، عرض طلبات متجر + `generate_invoice`، أصول ثابتة، مصروفات مقدمة ومستحقة، أسعار صرف وإعادة تقييم، مصادر دفع وحسابات استلام (عرض)، ضرائب (عرض).

> بعد إضافة `sales.refunds.*` وشخصيات QA الجديدة في `ensure-qa-users.ts` يلزم **نشر وبذر** على الإنتاج قبل أن تظهر الصلاحيات على حساب `qa-finance` الحالي.

## التبويبات المستخدمة

- المالية: حسابات الاستلام، قيود اليومية، دليل الحسابات، قبض العملاء، مدفوعات الموردين، مراجعة الدفعات، بنوك، أصول، مقدمات، مستحقات، صرف أجنبي، فترات، أرصدة افتتاحية، إقفال سنة، إعدادات محاسبية، …
- المبيعات → مدفوعات/ردود: قائمة الردود النقدية `/sales/payments?view=refunds` وتفاصيل `/sales/refunds/:id`
- التقارير → المالية (والأستاذ العام من رابط المالية)
- طلبات المتجر (عرض + توليد فاتورة حسب الصلاحية)

## مهام شائعة

### 1) تأكيد وترحيل دفعة طلب متجر

1. افتح طلب المتجر → تبويب المدفوعات (أو مسار التأكيد المعتمد).
2. نفّذ **تأكيد وترحيل (Confirm & Post)**.
3. النتيجة المتوقعة: دفع VERIFIED + سند قبض + قيد يومية متوازن.
4. إعادة الضغط آمنة: `alreadyPosted = true` ونفس سند القبض.

مرجع: PAY-2026-000040 → CR-2026-000039 → [JV-2026-000235](https://oms.haseb.org/finance/journal-entries/cf98525d-774c-419a-a368-522539b30813) (Dr/Cr 900).

### 2) توليد فاتورة طلب متجر

1. بعد التسوية، ولّد الفاتورة مرة واحدة.
2. توقع قيد فاتورة (إيراد + تكلفة إن وُجدت) وحالة PAID إن وُجدت دفعة مقدمة تغطيها.
3. إعادة التوليد تُرفض إن وُجدت فاتورة.

مرجع: INV-2026-000057 / JV-2026-000236.

### 3) قبض جزئي ثم كامل على فاتورة B2B

1. أنشئ سند قبض وخصّص على الفاتورة بمبلغ ≤ المتبقي.
2. تخصيص أكبر من المبلغ يُرفض.
3. بعد 600 ثم 900 على INV-2026-000060: PARTIALLY_PAID ثم PAID.

### 4) مدفوعات مورد جزئية/كاملة

1. من مدفوعات المشتريات سجّل دفعة جزئية ثم متبقية.
2. مرجع: PI-2026-000032 — SP-2026-000023 (200) + SP-2026-000024 (150).

### 5) رد مبلغ نقدي بعد مرتجع مبيعات

1. افتح مرتجع مبيعات مؤكداً له رصيد قابل للرد (مثال SR-2026-000016 بـ refundable **200**، أو بعد مرتجع كامل مثل SR-2026-000015).
2. من إجراءات المرتجع اختر **«رد مبلغ»** — أو أنشئ/أكد عبر API `/financial-transactions/refunds` (+ `/confirmed` عند الحاجة).
3. أكّد الرد بالمبلغ ≤ `refundableAmount`.
4. النتيجة المتوقعة: مستند CRF بحالة **CONFIRMED** + قيد يومية للرد + انخفاض رصيد العميل الدائن.
5. بعد رد كامل: `refundableAmount = 0` و`customerCreditBalance = 0`؛ كشف العميل يغلق على **0** لهذا المسار.

مراجع إنتاج:

| المستند         | المبلغ | ضد                          | الحالة                              |
| --------------- | ------ | --------------------------- | ----------------------------------- |
| CRF-2026-000001 | 450    | SR-2026-000014              | CONFIRMED                           |
| CRF-2026-000002 | 450    | SR-2026-000015 (Customer C) | CONFIRMED → رصيد قابل للرد/دائن = 0 |

قائمة الردود: https://oms.haseb.org/sales/payments?view=refunds  
تفاصيل: `/sales/refunds/:id`  
تصحيح ادعاء «لا API»: [VERSION-REFUND-RESOLUTION.md](../evidence/VERSION-REFUND-RESOLUTION.md).

### 6) قيد يدوي

1. أنشئ مسودة متوازنة (غير المتوازن يُرفض).
2. عدّل المسودة → رحّل → يمكن إعادة لمسودة ثم إعادة ترحيل (موثّق لـ JV-2026-000252).
3. **لا** تعدّل قيداً نظامياً ناتجاً عن فاتورة/قبض/رد — صحّح المستند المصدر.

### 7) أصل ثابت ومصروف مقدم

1. رسملة أصل (مثال FA-2026-000013 تكلفة 1200).
2. تفعيل مصروف مقدم (PE-2026-000018 بمبلغ 300 على 3 فترات).
3. تشغيل إهلاك دفعي / إثبات دوري للمقدمات: **لم يُشغَّل** (`ALLOW_GLOBAL_RUNS` ما زال OFF — يمس الشركة كلها).

## المراحل ومن المسؤول

| الحدث                 | أثر محاسبي                             | من                        |
| --------------------- | -------------------------------------- | ------------------------- |
| Confirm & Post        | Dr نقدية/بنك، Cr ذمم                   | مالية                     |
| فاتورة مبيعات         | Dr ذمم، Cr إيراد + COGS                | مالية / مخوّل فاتورة      |
| تكلفة شحن عند التسليم | قيد SHIPMENT_COST                      | ينشأ مع التسليم           |
| مرتجع مبيعات          | عكس إيراد/تكلفة ومخزون؛ رصيد دائن عميل | بعد تأكيد المرتجع         |
| رد نقدي عميل (CRF)    | صرف نقد؛ يقلّل الرصيد الدائن؛ قيد رد   | مالية / `sales.refunds.*` |
| فاتورة مشتريات        | Dr مخزون، Cr ذمم دائنة                 | مع التأكيد                |

## الدفع مقابل الشحن

المالية تغلق حالة الدفع دون انتظار الشحن. STO-2026-000083 مثال: مدفوع بالكامل + فواتير وقيود، والشحن لم يكتمل في ذلك السيناريو.

## أخطاء شائعة

| السلوك                               | التفسير            |
| ------------------------------------ | ------------------ |
| alreadyPosted                        | تكرار آمن          |
| fully paid — cannot accept payment   | لا دفعة إضافية     |
| Cannot edit system-generated journal | عدّل المصدر        |
| Journal entry is not balanced        | صحّح المدين/الدائن |
| Total allocated cannot exceed…       | خصّص ≤ مبلغ السند  |

## تقارير ذات صلة (موثّقة F7)

- ميزان المراجعة (متوازن؛ نطاق الجولة مدين 8922)
- أستاذ عام يطابق الميزان على الحسابات المفحوصة
- ميزانية عمومية: أصول = خصوم + حقوق ملكية
- قائمة دخل: صافي الدخل يطابق أرباح الفترة في الميزانية
- تدفق نقدي يعمل
- كشف عميل/مورد + تقادم ذمم
