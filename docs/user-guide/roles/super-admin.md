## المهام

> جميع القوائم تستخدم عناصر التحكم الموحدة: اكتب في أي قائمة منسدلة للبحث (تتطابق صيغ الحروف العربية)، وصف **«+ جديد»** يظهر أعلى القائمة إن كنت مخولاً بالإنشاء، و **×** يمسح الحقل الاختياري. فلاتر القوائم نوافذ منبثقة فيها خيار **«الكل»**.

### 1) إنشاء فئة منتج

- **المتطلبات المسبقة:** لا شيء.

1. المنتجات والمخازن ← **الفئات** ← **إضافة جديد**.
2. أدخل **الاسم** (إلزامي) و**الوصف**؛ حسابات الإيراد/المخزون/التكلفة/المشتريات اختيارية.
3. اضغط **حفظ**.

- **النتيجة المتوقعة:** رسالة «تم الحفظ» وتظهر الفئة في القائمة (J031).

![حوار إضافة فئة](../screenshots/audit/master-data_categories-create-filled.png)

### 2) إنشاء منتج بالمعالج وتفعيله

- **المتطلبات المسبقة:** فئة ووحدة قياس موجودتان.

1. المنتجات والمخازن ← **المنتجات** ← **إضافة جديد** ← يفتح «إضافة منتج» بأربع خطوات: **الأساسيات، التسعير والتجارة، المخزون، مراجعة وإنشاء**.
2. في **الأساسيات**: **الاسم بالعربية**، **الفئة**، **وحدة القياس** (إلزامية)، و**نوع المنتج** (مثل «شراء وبيع»).
3. في **المخزون**: فعّل **تتبع المخزون** ثم أدخل **الوزن / العرض / الارتفاع / الطول** (إلزامية للصنف المخزني). فعّل **متاح لفرص الاستثمار** إن كان سيُموَّل.
4. **التالي** حتى **مراجعة وإنشاء** ثم أنشئ. (يمكن «إنشاء كمسودة الآن» في أي خطوة.)
5. في حوار «تم إنشاء المنتج بنجاح» اختر **فتح هذا المنتج** ثم فعّله من قائمة الإجراءات (⋮).

- **النتيجة المتوقعة:** رمز تلقائي `PRD-…`، الحالة مسودة ثم «نشط» مع رسالة «تم تفعيل المنتج.» (J033، J034).

### 3) رصيد افتتاحي، تسوية، جرد فعلي

- **المتطلبات المسبقة:** منتج **نشط** مع تتبع المخزون، ومستودع نشط.

1. **حركات المخزون** ← **حركة جديدة** ← **الرصيد الافتتاحي**: المنتج، المستودع، **الكمية**، **متوسط التكلفة** ← **حفظ** ← «تم تسجيل الرصيد الافتتاحي.» (J039: 0→20).
2. **حركة جديدة** ← **تسوية المخزون**: **الاتجاه** (زيادة الكمية/نقص)، الكمية، **السبب** (إلزامي، مثل «تصحيح») ← **حفظ** ← «تم تسجيل الحركة.» (J040: 20→22).
3. **الجرد الفعلي** ← **جرد فعلي جديد**: المستودع، ابحث واختر المنتجات ← **حفظ** ← أدخل الكمية المعدودة ← أكّد ← «تم تأكيد الجرد الفعلي.» (J042: الفرق −1 يُسجَّل حركة).

- **النتيجة المتوقعة:** كل عملية تنشئ حركة غير قابلة للتعديل؛ تظهر في **حركات المخزون** بفلتر المنتج والنوع (J043).

### 4) عميل ومورد جديدان

1. المبيعات ← **العملاء** ← **إضافة جديد** ← الاسم وبيانات التواصل ← **حفظ** (رقم `PT-…` تلقائي، J035).
2. المشتريات ← **الموردون** ← **إضافة جديد** بنفس الطريقة (J037).

![حوار العميل](../screenshots/audit/sales_customers-create-filled.png)

### 5) اعتماد فاتورة شراء مرسلة للاعتماد

- **المتطلبات المسبقة:** فاتورة شراء بحالة «بانتظار الاعتماد» أرسلها موظف المشتريات.

1. المشتريات ← **فواتير الشراء** ← افتح الفاتورة ← **اعتماد** ثم **تأكيد**.

- **النتيجة المتوقعة:** «تم تأكيد فاتورة الشراء — تم استلام المخزون.»؛ قيد يومية وحركة «استلام» في السجلات المرتبطة (J051).

![فاتورة شراء مؤكدة](../screenshots/audit/purchasing-pi-confirmed.png)

### 6) قيد يومية يدوي

1. المالية ← **قيود اليومية** ← جديد ← **دفتر اليومية** (مثل «دفتر اليومية العامة — GJ»)، **تاريخ القيد**، **المرجع**، **الوصف**.
2. في جدول **«بنود القيد»** أضف بندين (**الحساب**، **مدين** / **دائن**) حتى يظهر **متوازن** ← **حفظ**.
3. اضغط **ترحيل** وأكّد.

- **النتيجة المتوقعة:** «تم ترحيل القيد.»، رقم `JV-…` وحالة «مرحّل» مع أزرار إعادة إلى مسودة / عكس / نسخ / طباعة (J086–J087: JV-2026-000336).

![قيد معبأ](../screenshots/audit/admin-je-filled.png)
![قيد مرحّل](../screenshots/audit/admin-je-posted.png)

### 7) بدء شحنة لطلب متجر

1. المبيعات ← **طلبات المتجر** ← حدد الطلب ← **تغيير حالة الشحن** ← **الحالة الجديدة** = «جاهز للشحن» ← **تغيير الحالة**.

- **النتيجة المتوقعة:** «تم تحديث 1 طلبًا بنجاح» وتُنشأ الشحنة؛ يكمل موظف الشحن بعدها (J078، J082).

![تغيير حالة الشحن](../screenshots/audit/shipping-change-status-STO-2026-000126.png)

### 8) استلام دفعة من فاتورة بيع

1. افتح فاتورة البيع المؤكدة ← من إجراءات الفاتورة (**المزيد**) اختر **استلام دفعة** (يفتح «سند قبض عميل» معبأً بالعميل والمبلغ والفاتورة).
2. راجع **حساب الاستلام** و**التخصيصات** ← **تأكيد**.

- **النتيجة المتوقعة:** «تم التأكيد.»، سند `CR-…` وحالة الفاتورة «مدفوعة بالكامل» (J067 — مثبت في جولة 7e61bd5: CR-2026-000053؛ في الجولة النهائية سدّدت المالية الفاتورة بسند قبض مباشر فلم يلزم).
- الشاشة نفسها «سند قبض عميل» — اللقطتان من الجولة النهائية (المالية):

![سند قبض عميل معبأ](../screenshots/audit/finance-receipt-filled.png)
![سند مؤكد](../screenshots/audit/finance-receipt-confirmed.png)

### 9) تكلفة مرحلة: إنشاء ← اعتماد ← ترحيل

- **المتطلبات المسبقة:** فاتورة شراء **مؤكدة**، وفئة تكلفة قابلة للرسملة.

1. المشتريات ← **التكاليف المرحلة** ← إنشاء («تكلفة مرحلة جديدة»): **فاتورة الشراء**، **مزود الشحن / التخليص**، **المرجع**، **التاريخ**، **طريقة التوزيع** (مثل «حسب قيمة الشراء»). **العملة** تُضبط تلقائياً على **EGP** لفواتير العملة الأساسية.
2. في **سطور التكلفة**: **فئة التكلفة** (مثل «شحن وارد»)، **الوصف**، **المبلغ الصافي**، **ضريبة القيمة المضافة** ← **إضافة سطر** عند الحاجة ← **حفظ**.
3. راجع **معاينة التوزيع** (نصيب كل منتج)، ثم اعتمد المستند ← «تم اعتماد التكاليف المرحلة — تم تثبيت التوزيع.»، ثم رحّله ← «تم ترحيل التكاليف المرحلة — تمت رسملتها ضمن المخزون.»

- **النتيجة المتوقعة:** الحالة «مرحّل»، وفي **السجلات المرتبطة** فاتورة الشراء وقيد يومية «مرحّل» (J056: LC-2026-000002، 25 EGP، JV-2026-000329).
- **فئات التكلفة (9):** الجمارك، الشحن الوارد، تجهيز المنتج للبيع = **قابلة للرسملة** (اقتناء المخزون)؛ تجهيز وتغليف الطلبات = **التنفيذ**؛ الطباعة، التغليف، علب مخصصة، أخرى = «أخرى» حتى تقرر الإدارة. التصنيف قابل للتعديل من **التكاليف ← فئات التكلفة**. **«تكلفة المنتج» غير قابلة للرسملة عمداً** — فهي مضمّنة في سعر فاتورة الشراء.

### 10) مراجعة الإعدادات والمستخدمين

1. الإعدادات ← **المستخدمون** ← **مستخدم جديد**؛ الصلاحيات تُمنح مباشرة للمستخدم («المسمى الوظيفي تسمية فقط»).
2. **ترقيم المستندات**: الأرقام تُنشأ تلقائياً؛ «إضافة سلسلة ترقيم» عند الحاجة.

- جولة التدقيق **عرضت** الصفحات فقط ولم تغيّر إعدادات (J129–J137).

**الصلاحيات بعد تحسينات الأمان (64679e7):**

- **المنتقيات حسب الدور:** من لا يملك دليل الشركاء يرى في قوائم اختيار العميل/المورد الاسم والرمز فقط (لا جهات اتصال ولا أرصدة ولا بيانات حساسة)؛ الشحن والموارد البشرية لا يصلون للكتالوج (62 PASS).
- **الجلسات:** تسجيل الخروج يمسح كل البيانات المخزنة مؤقتاً، فلا يرى المستخدم التالي في نفس التبويب شيئاً من بيانات السابق (25 PASS). إعادة تحميل التبويبات الأخرى عند الخروج جزء من الإصلاح لكنها لم تُقَس في التقرير.
- **إجراءات الكتابة تتطلب الصلاحية المطابقة:** صفحات «جديد» تُفتح فقط لمن يملك صلاحية الإنشاء؛ والعناصر التي لا يستطيع المستخدم فتحها مخفية من القائمة.
- **صلاحيات المجموعات** (مجموعات العملاء/الموردين) لم تعد تمنح ضمنياً الوصول لكامل دليل العملاء أو المنتجات — امنح الصلاحية المحددة بدلاً من ذلك.
- إن أبلغك موظف بـ «الوصول مرفوض» في عملية يحتاجها، امنحه **الصلاحية المحددة** لتلك العملية من محرر المستخدم.

### 11) إعداد طرق الدفع للمطابقة والتسوية

تُحدد طريقة الدفع **أين يُرحَّل** تأكيد المالية وهل تمر بمساحة **مطابقة المدفوعات**. (الأدلة: جولة **DEMO-PDR-20260927** على 0331a58 — P008–P013.)

- **المتطلبات المسبقة:** حساب **أصول** فرعي قابل للترحيل لكل طريقة (حساب تسوية وسيط)، وحساب بنكي لاستلام تحويلات المزوّد.

1. المالية ← **دليل الحسابات** ← **حساب جديد**: **الاسم** (مثل «Tamara clearing»)، **نوع الحساب** «أصول»، **طبيعة الحساب** «حساب فرعي»، **الحساب الأب** (مثل «النقدية والبنوك») ← **حفظ** ← «تم الحفظ». **الرمز** يُقترح تلقائياً حسب موقعه في الشجرة ولا يتكرر («لا يمكن للموظف العادي كتابة رمز يدوياً»؛ **كود مخصص** لأصحاب الصلاحية المتقدمة فقط). في الجولة: 114 Tamara clearing، 115 Bank transfer clearing، 116 Settlement bank.
2. المالية ← **طرق الدفع** ← **إضافة جديد** (أو تعديل طريقة قائمة): **الاسم**، **الوصف**، **الحساب المرتبط** (إلزامي — حساب التسوية الوسيط)، **تتطلب مطابقة**، **نشطة** ← **حفظ**.
   - **تتطلب مطابقة مفعّلة** (مثل Tamara): تظهر الطريقة في **مطابقة المدفوعات**، وتُرحَّل مطالباتها بالمطابقة مع كشف المزوّد ثم تُسوّى بتسوية دفعة.
   - **غير مفعّلة** (مثل التحويل البنكي): تؤكد المالية وترحّل من **مراجعة المدفوعات** مباشرة على الحساب المرتبط، ولا تدخل التسويات.
3. حساب البنك الذي تُودَع فيه تحويلات المزوّد يجب أن يكون **حساب استلام** (يظهر في «أودع في (البنك)»). صفحة **المالية ← الحسابات** (`/finance/receiving-accounts`) ما زالت «قريباً»، فأُنشئ حساب الجولة عبر API (P013) — **لا يوجد مسار واجهة موثّق لإنشائه بعد**.
4. المالية ← **إعدادات الحسابات**: تأكد من **رسوم بوابة الدفع** (قسم «التكاليف التشغيلية المباشرة» — على الإنتاج 522 عمولات بوابات الدفع) و**حساب فروق الصرف** (قسم «الحسابات العامة» — على الإنتاج 546 فروقات العملة المحققة). التسوية تستخدمهما تلقائياً (P006: كلاهما مضبوط).

- **النتيجة المتوقعة:** «تم الحفظ»؛ طريقة Tamara (QA) بحساب 114 و«تتطلب مطابقة» ظهرت في مطابقة المدفوعات، وطريقة Bank transfer (QA) بحساب 115 لم تظهر وأُكِّدت من مراجعة المدفوعات (P011، P012، P047، P065).
- **تغيير الحساب المرتبط ممنوع** ما دامت هناك مطالبات «بانتظار التسوية» على الطريقة (يُرفض مع عدد المطالبات)، ويُسمح بعد تسويتها (اختبار آلي L3). تغيير «تتطلب مطابقة» لا يعالج السجلات السابقة بأثر رجعي.
- **إجراء مطلوب من المالك:** طرق الدفع الحقيقية على الإنتاج (تمارا، Mamo Pay، …) **ليس لها حساب مرتبط** حالياً — اربط لكل منها حساب تسوية وسيط (أصول) قبل تفعيل «تتطلب مطابقة» واستخدامها في المطابقة. (المصدر: `specs/payment-declaration-reconciliation/handoff.md` — إجراءات المالك.)

| ---------------------------- | ------------------------------- | -------------------------------------------------------------- |
| إنشاء منتج ← تفعيل           | مدير النظام / المنتجات          | يصبح متاحاً في البنود والحركات                                 |
| رصيد افتتاحي / تسوية / جرد   | مدير النظام / المخزون           | حركة مخزون (OPN / ADJ / CNT)؛ الرصيد = مجموع الحركات           |
| تحويل مخزون                  | المخزون                         | حركة خروج + دخول بين مستودعين — **محجوب حالياً** (مستودع واحد) |
| اعتماد وتأكيد فاتورة شراء    | المعتمد                         | حركة «استلام» + قيد يومية + ذمة مورد                           |
| قيد يدوي ← ترحيل             | مدير / محاسب مخول               | يؤثر على الأستاذ والميزان                                      |
| تكلفة مرحلة ← اعتماد ← ترحيل | مدير النظام                     | تثبيت التوزيع ثم رسملة التكلفة في قيمة المخزون + قيد يومية     |
| بدء الشحنة                   | مدير (صلاحية `shipping.manage`) | يُنشئ شحنة يكملها موظف الشحن؛ للدفع المسبق يكفي إبلاغ كامل     |
| طريقة دفع ← حساب مرتبط       | مدير النظام                     | يحدد حساب المدين عند تأكيد/مطابقة المالية                      |
| «تتطلب مطابقة»               | مدير النظام                     | الطريقة تظهر في مطابقة المدفوعات وتُسوّى بتسويات المزوّد       |
