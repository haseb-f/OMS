# المشتريات (Purchasing)

حساب QA الدائم (بعد البذر): `qa-purchasing@oms.haseb.org` — دور **مدير التشغيل** مع صلاحيات المشتريات + مدفوعات الموردين (لا توسيع صلاحيات موظف عام غير ذي صلة).

التحقق الوظيفي لـ F4 تم عبر `qa-admin`. متصفح الشخصية: **BLOCKED** حتى نشر/بذر `ensure-qa-users.ts`.

## التبويبات المستخدمة

- المشتريات: الموردون، مجموعات الموردين، عروض أسعار الشراء، أوامر الشراء، فواتير الشراء، مرتجعات الشراء، التكلفة الواصلة (صفحة تُحمَّل؛ **منطقها غير مختبر في DEMO**)
- المالية → مدفوعات الموردين (للدفع)

## مهام شائعة

### 1) عرض شراء → أمر → فاتورة

1. أنشئ عرض شراء (RFQ/عرض) بإجمالي صحيح.
2. حوّل/اعتمد أمر الشراء.
3. أكّد فاتورة الشراء — يُنشأ قيد واحد متوازن ويستلم المخزون.

مرجع DEMO:

| المستند | الرقم                                                                                                       | المتوقع                 |
| ------- | ----------------------------------------------------------------------------------------------------------- | ----------------------- |
| عرض     | [PQ-2026-000003](https://oms.haseb.org/purchasing/purchase-quotations/e294e7fe-dc49-40d3-97df-670328a93d6b) | 350                     |
| أمر     | [PO-2026-000004](https://oms.haseb.org/purchasing/purchase-orders/f98d36f9-01cb-4653-94d2-ee3a26d75256)     | APPROVED 350            |
| فاتورة  | [PI-2026-000032](https://oms.haseb.org/purchasing/purchase-invoices/9b454c23-67af-44df-aca6-aa2d6332609e)   | 350 ثم PAID بعد الدفعات |

### 2) دفع جزئي ثم كامل للمورد

1. من مدفوعات الموردين سجّل 200 ثم 150 على نفس الفاتورة.
2. الحالة: PARTIALLY_PAID (متبقي 150) ثم PAID.
3. القيود: JV-2026-000247 و JV-2026-000248.

### 3) مرتجع شراء بعد السداد الكامل

1. أنشئ مرتجع شراء بكمية ضمن المستلم.
2. أثر DEMO: PR-2026-000008 بمبلغ 70، حركة مخزون −2، قيد JV-2026-000249.
3. كشف المورد بعد المرتجع: رصيد مدين 70 (المورد مدين للشركة بعد إرجاع بضاعة مدفوعة) — ثم تأثر لاحقاً بمشتريات أخرى في F5/F7.

### 4) طبقة تكلفة للمخزون (مع F5)

فاتورة شراء لاحقة PI-2026-000033 (360 = 10 @ 36) تُحدّث المتوسط المتحرك لصنف Book Lab إلى 33 — راجع دور المخزون/المالية.

## المراحل ومن المسؤول

| المرحلة                 | من                    |
| ----------------------- | --------------------- |
| عرض وأمر شراء           | مشتريات               |
| استلام عبر فاتورة مؤكدة | مشتريات (+ أثر مخزون) |
| دفع المورد              | مالية                 |
| مرتجع                   | مشتريات               |

## الدفع مقابل الشحن

مسار المشتريات منفصل عن شحن طلبات المتجر للعملاء. لا تخلط حالة دفع المورد مع شحن STO.

## أخطاء شائعة

- إعادة تأكيد فاتورة الشراء لا تنشئ قيداً ثانياً (موثّق).
- كمية افتتاح/حركة سالبة أو غير موجبة تُرفض في فحوصات المخزون ذات الصلة.
- التكلفة الواصلة (Landed cost): **NOT TESTED** وظيفياً في هذه الجولة.

## تقارير ذات صلة

- كشف مورد من التقارير المالية (`supplierStatement`) — موثّق.
- `/reports/purchasing` = **قشرة «قريباً»**.
