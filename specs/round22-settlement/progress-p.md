## Contract as implemented (exact names)

- Summary (sales + purchase list item and detail, open-invoices row; aging invoice line): `grandTotal, paidTotal,
allocatedTotal (= paidTotal), creditedTotal, remainingBalance, paymentStatus` + `currencyCode` (list / detail / open rows;
  aging lines also `currencyId`, `allocated` kept = paid).
- Settlement history: `{ summary: {grandTotal, paidTotal, allocatedTotal, creditedTotal, remainingBalance, paymentStatus,
currencyCode}, entries: [{ kind: 'PAYMENT'|'CREDIT_NOTE', documentId, documentNumber, documentType
(CUSTOMER_RECEIPT|SUPPLIER_PAYMENT|SALES_RETURN|PURCHASE_RETURN), date (ISO: allocation date / return posting date),
status, amount, currencyCode, allocationId?, canUnallocate, canCancel }] }` sorted by date. DRAFT voucher lines are listed
  with `status: 'DRAFT'` (flags false; they pay nothing). Route = the detail's `view` right; unknown / archived → 404;
  `canUnallocate` = confirmed + `customer-receipts|supplier-payments` edit; `canCancel` = confirmed + cancel right, false for
  store-order claim receipts. Credit-note `amount` = credit applied to this invoice.
- `PATCH /financial-transactions/{receipts|payments}/:id/allocations/:allocationId` `{ allocatedAmount }` (positive, ≤ 2
  dp; action `edit`) → fresh voucher. Errors: 400 "…remains unallocated…", 400 `ALLOCATION_EXCEEDS_INVOICE_BALANCE`
  (`details.remainingBalance / paidTotal / creditedTotal`), 404 allocation, 409 `ADVANCE_REFUND_ALLOCATION`, 400 not CONFIRMED.
- Aging (`/accounting/reports/ar-aging|ap-aging`): `partners[]` per partner × currency with the existing fields +
  `currencyId, currencyCode`; `invoices[]` + `currencyId, currencyCode, paidTotal, creditedTotal`; `totalsByCurrency[] {
currencyId, currencyCode, current, days31to60, days61to90, over90, total, unapplied, net }`; `totals` kept (deprecated)
  = functional currency only, named by `totalsCurrencyId / totalsCurrencyCode`.
- `sortBy`: sales invoices `invoiceNumber, customer, referenceNumber, status, subtotal, discountTotal, taxTotal,
grandTotal, confirmedAt, createdAt, updatedAt`; purchase the same with `supplier`; vouchers `transactionNumber,
referenceNumber, description, status, amount, feeAmount, transactionDate, confirmedAt, createdAt, updatedAt, customer,
supplier, partner, counterparty, paidFrom, receivingAccount, costCenter`. Paid / remaining are not server-sortable.
- New error codes: `FEE_EXCEEDS_AMOUNT`, `AGENT_COLLECTION_NOT_ALLOCATABLE`, `COMPANY_MISMATCH`,
  `ALLOCATION_EXCEEDS_INVOICE_BALANCE` (was a plain-string 400), `INVOICE_ARCHIVE_SETTLEMENT`.

## Limitations

- P4 closing values applied credit at the invoice rate and only absorbs a rounding residue (≤ 0.05); an invoice re-settled
  after an earlier settling line was removed can keep ≤ 1 cent, reported by `PARTNER_AGING_MISMATCH`.
- Growing an existing line with Allocate keeps the line's first `allocationDate` (as-of aging counts the added part from it).
- Invoices have no row-level scope: "cannot open" = no `sales-invoices|purchase-invoices.view` (403 by the guard, as the
  detail) or unknown / archived (404).
- Foreign-currency `PARTNER_AGING_MISMATCH` is only decidable when nothing is open / unapplied in that currency.
