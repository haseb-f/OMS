## Not covered through the API (covered by integration tests)

- The receipt `feeAmount` can only be set by bank-line reconciliation (`confirm-sales-invoice-receipt`; the receipt DTO
  strips it). There was no unreconciled bank line in the clone, so the D5 receipt-fee cap is covered by
  `r22-settlement.integration.spec.ts`. J14 exercises the same `assertFeeWithinAmount` through `/payments/:id/fee`.
- Foreign-currency FX adjustments on allocate / unallocate (P1 / P2 / D6) were not run. The clone has no FX-rated
  invoice fixture, so these are covered by the stream P specs.

## Observations (not defects against D4 / D10)

- **O1.** The counter-account allow-list is built from the accounts mapped **now**. In this demo clone
  `PostingSettings.agentFundsPayableAccountId` is null, left that way by earlier fixtures. As a result, agent payable
  accounts (`AGT-PAY-*`, `CMP-PAY-*`, `R17-PAY-*`) are offered for IN and OUT. One of them, `AGT-PAY-5EDAFA`, already
  carries 55 partner-tagged agent-ledger lines. If the allow-list should never offer an account that holds
  partner-tagged sub-ledger history, it would also need to exclude accounts with partner lines. That is an owner
  decision. The script uses equity 311 for both directions.
