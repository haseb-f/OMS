### 1.3 Clipping risks (fixed widths, `theme/tokens.css:82-95`)

- Tokens: quantity 80px, discount 80px, **price 96px**, **line-total 104px**, unit 56px, tax 120px, warehouse 180px, actions 40px, product-min 220px.
- `documentLineCellClass` is `overflow-hidden whitespace-nowrap` (`document-line-table.tsx:23`) and numeric cells add input `px-2` + cell `px-2` + border (≈ 34px chrome). A 96px price column leaves ≈ 62px of digits → `1,234,567.89` (12 glyphs) clips; line total 104px clips at ~8-digit amounts with separators. Quantity 80px clips decimals like `12,500.000`.
- Unit column 56px truncates any unit name longer than ~5 chars (`product-line-items-grid.tsx:985` `truncate`).
- `JournalEntryLinesGrid` debit/credit = 96px, `MoneyInput align="center"` (:309-322); table is `w-full table-fixed` with **no min-width** (:182) so on narrow widths account/description columns collapse instead of scrolling; no stacked mode at all.
- `AllocationGrid` amount input 96px, `text-center` (:116-123).
- Nested scroll containers: `ui/Table` already wraps in `overflow-x-auto` (`components/ui/table.tsx:9`); `DocumentLineTable` (:58), journal grid (:181) and allocation grid (:75) add another `overflow-x-auto` div → double scroll container.
- EnterpriseModal `ModalSection columns={4}` uses **viewport** breakpoints (`modal-section.tsx:10-12`), so a 768px `lg` modal on an xl screen still gets 4 columns.

### 1.4 Duplicated logic / inconsistencies across editors

1. **Three totals presentations:** `DocumentTotalsFooter` (commercial), `CreateOperationTotals`/`Summary` boxes (journal :660, payments `payment-summary.tsx:42`, store-order create), grid `TableFooter` (journal). Invoices show grand total twice (totals footer + `InvoicePaymentSummary` "Total").
2. **Numeric alignment:** commercial lines `text-end` with shared edge; journal + allocation grids `text-center`.
3. **Header chrome:** journal/allocation grids `rounded-md` + `bg-muted/50`; `DocumentLineTable` `rounded-xs` + `bg-muted/40`.
4. **Action model:** only commercial editors use `DocumentActionBar`; FT editor, journal, landed cost, opening balances, commission plans render inline button rows. Mobile sticky action bar exists only for commercial docs.
5. **Cancel confirmation bypasses the action bar's `confirm`:** 10 editors open a separate page-level `ConfirmationDialog` via `onAction: () => setCancelTarget(true)` (e.g. `sales/invoices/invoice-editor-page.tsx:326` + :455; purchasing/sales order/return/quotation/payment/refund pages) while other transitions use `confirm:` inside `DocumentActionBar` (:239, :288).
6. **"More details" collapsible + activity timeline mapping + loading placeholder** copy-pasted in `commercial-document-editor.tsx:164-181,309-350`, `financial-transaction-editor.tsx:150-163,330-358`, journal editor (~:695-740).
7. **RelatedRecordsPanel placement:** inside card under header (commercial :206), above card (journal :425, landed cost :283, receipt pages).
8. **Stale contract comment:** `DocumentTotalsFooter` says it "NEVER computes… no client-side estimate" (`document-totals-footer.tsx:9-17`) but `CommercialDocumentEditor` feeds it a client-side preview (`:146-162`).
9. **Locale-dependent money formatting** (the hydration/digit bug `lib/money` was created to fix) still in `payment-summary.tsx:31-38`, `invoice-payment-summary.tsx:11-16` (local duplicate `formatMoney`), `allocation-grid`, `journal-entry-lines-grid`, `open-invoices-table`, `party-payments-panel` — 31 `toLocaleString(undefined…)` occurrences in `.tsx`.
10. **Validation**: commercial pages validate on save and show the first error as a toast (`invoice-editor-page.tsx:146-168`) — no field highlighting except line price (`showErrors`). Store-order create/lead convert highlight inline (`showErrors`, `FieldMessage`).

## 6. Toast / feedback

- Canonical wrapper `lib/toast.ts` (default durations :19-24; `reportApiError` :67). All modules import from `@/lib/toast` (167 files); `sonner` imported directly only in `components/ui/sonner.tsx` and `lib/toast.ts`. Single `<Toaster />` in `providers/app-providers.tsx:24`.
- `reportApiError` adopted in only 25 files; **339** inline `error instanceof ApiError ? error.message : …` repeats remain. Of those, **155 fall back to hard-coded English** (`"Something went wrong."`, `"Failed to load …"`) in an Arabic-first UI — purchasing 48, sales 46, finance 28, store-orders 7, master-data 7 (e.g. `sales/payments/receipt-editor-page.tsx:110,204,222`, `journal-entry-editor-page.tsx:210,276,294,321,335,377`).
- Toaster position `bottom-right` on desktop is physical, not mirrored for RTL (`components/ui/sonner.tsx:27`); top-center on phones to clear the action bar.
- Success toasts are consistent for save/transition (`common.saved`, module `toasts.*`); validation failures also surface as error toasts (see §2) rather than field errors. Silent failures: sales dashboard load (§3), investors overview (§3).
