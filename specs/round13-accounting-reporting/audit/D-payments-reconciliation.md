# Audit D — payment methods, sources, reconciliation (2026-10-06)

- `PaymentMethod` (payment_methods): name, `accountId` (clearing, ASSET posting leaf), requiresReconciliation, isActive; no currency/company. Referenced by SalesOrder, Expense, CapitalContribution, DistributionPayment, AgentPaymentDestination, Payment (optional), PaymentStatementImport/Line, PaymentSettlement.
- `PaymentSource` (payment_sources): name, code, sortOrder, isDefault, defaultChartOfAccountId (suggestion), feePercentage/feeFixedAmount (estimate). Referenced by `Payment.paymentSourceId` (**required**) and `FinancialTransaction.paymentSourceId`. **Same "how paid" concept as PaymentMethod**; declaration derives source from method by case-insensitive _name match_ → default (`payment-declaration.core.ts:208-250`). Seeds do not overlap, so it usually falls to the default.
- `ReceivingAccount`: bank/cash destination (required `chartOfAccountId`, currency). Full API CRUD but web page is `ComingSoonPage` (nav hidden). Distinct responsibility.
- `PaymentTerm`: credit terms, distinct.
- Screens: Payment Methods `/master-data/payment-methods`; Payment Sources `/finance/payment-sources` (**redundant**); reconciliation `/finance/payment-reconciliation/[methodId]`; bank transactions `/finance/bank-transactions`.
- Provider statements: import FILE / GOOGLE_SHEET / MANUAL; file mapping guessed each time (`suggestStatementMapping`) — **no reusable saved mapping** for files. Re-import safe: `@@unique([paymentMethodId, dedupeKey])`, planner CREATE/DUPLICATE/UPDATE/REAPPEARED/EXCEPTION. Line states UNMATCHED/MATCHED/EXCEPTION/IGNORED; matches ACTIVE/REVERSED; claim settlement NOT_APPLICABLE/AWAITING/PARTIALLY/SETTLED. Row locks + DB CHECK bounds. `PaymentMatch` has no unique (line, payment). Refunds / negative rows **rejected**; REFUNDED/CHARGEBACK rows classed FAILED. No refund matching.
- Journals: full allocation → Customer Receipt FT (Dr method clearing / Cr AR). Settlement `PaymentSettlement` (idempotencyKey unique) Dr bank + Dr commission + FX / Cr clearing — grouped payouts supported (settlement lines).
- Bank transactions engine separate; `matchedPaymentId` not unique; `findAdoptableClaim` accepts MATCHED claims without checking `PaymentMatch` → **two engines can act on one Payment**. **Gap.**
- Import Center has `ImportMappingTemplate` (`@@unique([importType, name])`) — not used by payment statements.
