# Accounting review — financial statement calculations (workstream ACC)

Status: implemented locally 2026-09-29, not committed. Round 2 (independent review fixes R1–R8): §11. Scope: Income Statement, Statement of Financial
Position (Balance Sheet), Trial Balance, Cash Flow — API `apps/api/src/accounting/reports/*`, web tabs
`apps/web/src/app/(shell)/reports/finance/*-tab.tsx`, `components/accounting/financial-report/*`.
No journal entry or data was changed and no migration was added. The one posting-path change is round 2's fail-closed refusal of Year Closing carry-forward (P1 / R8); it creates nothing.

This document does not claim the statements "comply" with any standard. It records which presentation
requirements they now follow, and the tests and reconciliations that prove the arithmetic.

## 3. Classification method (report layer, no schema change)

`statement-classification.ts` resolves every account to exactly one statement line:

1. **Own role**: the account is configured in Posting Settings (every `POSTING_ROLE_SETTINGS` field plus the agent accounts), product-category revenue / COGS / inventory / purchase, customer-group revenue, supplier-group purchase, supplier-profile expense, payment-method clearing account, receiving account (cash), or partner control type. If an account has several roles on different lines, the first in priority wins and warning `ROLE_CONFLICT` is raised.
2. **Otherwise**, the nearest ancestor with a role, or the nearest ancestor that is a **standard OMS COA header** with the same account type as its definition in `standard-chart-of-accounts.ts`:
   - Income Statement: 41 Revenue, 42 Returns & discounts, 43 Other income, 51 Cost of sales, 52 Selling & distribution, 53 Administrative, 54 Other expenses.
   - Balance Sheet: 11–14, 16, 21–23 current; 15 non-current.
3. **Otherwise UNCLASSIFIED.** The account is shown in its own section ("Unclassified accounts (effect on profit)" / "Assets / Liabilities not classified current / non-current") with warning `UNCLASSIFIED_ACCOUNTS` listing the accounts. It is included in every total, never dropped.

Role → line tables are in `PNL_ROLE_LINES` and `BS_ROLE_GROUPS`. Cash-flow activity by counterpart (`classifyCashFlowAccount`):

- cash set → movement between cash items;
- FX line → FX;
- EQUITY, finance-cost line, investor profit payable, non-current liability → financing;
- non-current asset → investing;
- everything else → operating.

No COA column or migration was needed. Recommended follow-up: an optional `reportingLine` override on the COA (open point P5).

### 4.5 All reports — shared rules

- One scope helper, `report-scope.ts`: status (POSTED + REVERSED; DRAFT only with `postedOnly=false`, flagged `DRAFTS_INCLUDED`), soft-delete, company / branch / cost center / project / transaction-currency scope, inclusive UTC calendar days, opening = before `dateFrom`, as-of = end of the `dateTo` UTC day. The Income Statement additionally excludes YEAR_CLOSING.
- Every statement is built from the same per-account debit / credit sums, so the statements tie by construction. The tests and the live script prove it.
- `CARRY_FORWARD_OPENING_ENTRY` warning: a POSTED `OPENING_BALANCE` entry dated after a Year Closing (open point P1).
- Print / export: Income Statement, Balance Sheet, Trial Balance and Cash Flow are not paged. Screen, print and Excel / CSV are built from the same `lines` and `summary` by `buildFinancialReportDocument`, and line labels resolve through `line-label.ts`. New structural rows (`is-*`, `bs-*`, `cf-fx-effect`, `prior-unclosed-earnings`) were added there. Paged General Ledger / Journal Report exports use `fetchAllReportPages` with the same params (unchanged, reviewed).

## 5. Web tabs

- **Income Statement:** summary = Net revenue, Gross profit, Operating profit, Net profit / loss. Warnings caption with an account list (`report-warnings.tsx`).
- **Balance Sheet:** summary adds Current-year profit and Cash & cash equivalents. The check uses the API difference. Unbalanced entries appear as a warning.
- **Trial Balance:** check covers period, opening and closing. Integrity warnings are shown.
- **Cash Flow (activities):** summary = Opening, Operating, Investing, Financing, FX effect (when non-zero), Closing. Check card "Opening + activities = closing cash" compares the computed closing with the ledger closing. Caption note for excluded internal transfers.

All tabs reuse `FinancialReport` and the shared summary / check / notice slots. There is no bespoke table. i18n is under `reports.finance.statementLines.*`, `statementSummary.*` and `statementWarnings.*` (ar / en).

## 9. Limitations

- Classification relies on the configured mappings and the standard COA header codes. A renamed or recoded header stops being recognised, and its accounts become Unclassified (visible, never dropped).
- `unbalancedEntries` drill-down ignores company / branch scope and is diagnostic only.
- No comparative-period columns, and no notes (IAS 1.38).
- Production was not reconciled (code not deployed). Run `tmp/acc/reconcile.mjs` with `API=` against Preview after deploy.
- The web tabs were not verified in a browser in this workstream. The master's single browser pass should cover the four tabs.
