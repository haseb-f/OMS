# R15 decisions

Adopted by the implementation lead under the owner's 2026-10-07 brief (which pre-authorizes commit / push / one
combined deploy and targeted test-data cleanup). "Open" items carry the recommended default that is implemented; the
owner can override.

## Store-order lifecycle (brief §5)

| Id     | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | Status  |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------- |
| D15-1  | **Reservation at creation.** Every creation path (manual, lead conversion, Excel/Sheets import, agent portal, internal agent order) reserves the stock lines right after the order commits, regardless of prepaid/COD. Reservation is the existing reserved ledger (`RESERVATION` under reference `STORE_ORDER:<order>`), not a stock transfer: owned stock is unchanged, available = on-hand − reserved drops at once, and the order shows its allocation.                                                                                                                                                                                                                            | Adopted |
| D15-2  | **Insufficient stock.** Reservation is per order line (a kit line = all its components or none). A line that cannot be fully reserved is not reserved at all; the order is saved with `stockStatus = SHORT` and the shortage (product, warehouse, required, available) on the order — never counted against available, never silently oversold. Dispatch of an unreserved line is refused; the user retries ("Reserve now", per order or in bulk oldest-first) or ships the reserved lines only (partial dispatch, D15-5). The order forms show availability per line before submit.                                                                                                   | Adopted |
| D15-3  | **Payment never gates the physical flow.** Reservation, dispatch, delivery and return ignore payment status; the R5 prepaid "declared before shipping" gate is removed (owner rule in this brief).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | Adopted |
| D15-4  | **Goods in transit = system warehouse `WH-TRANSIT` (role TRANSIT).** Dispatch (shipment SHIPPED / OUT_FOR_DELIVERY, inside the shipment transaction) releases the order's reservation and transfers the dispatched quantities warehouse → transit (TRANSFER pair, reference `STORE_ORDER_TRANSIT:<order>`, idempotency keyed per shipment line). If the stock cannot be secured the transition is refused with the reason. No journal at dispatch: goods in transit are still company inventory at the same moving average (control passes at delivery); the valuation report shows the transit warehouse separately. Transit and damaged warehouses never count as available-to-sell. | Adopted |
| D15-5  | **Partial dispatch / partial delivery (company orders).** A shipment carries lines (`ShipmentLine`): dispatch may ship any reserved, not-yet-dispatched quantity (default: all). Delivery may record accepted quantities per line (default: all shipped). One sales invoice per delivered shipment (`SalesInvoice.shipmentId`) for the accepted quantities (line amount prorated). Undelivered quantities stay in transit as RETURNING until received back. Agent orders ship whole; a partially refused agent parcel goes through the agent return flow.                                                                                                                              | Adopted |
| D15-6  | **Delivery = recognition (R14 D3-1 kept).** Invoice + `SALES_DELIVERY` out of transit + COGS + fulfillment/shipment cost post together, after the courier status commits (a status is never lost); failures stay on the order (`recognitionStatus FAILED`, red banner, retry). Pickup orders issue straight from the warehouse at COLLECTED. Estimated operational cost (order economics, `StoreOrderFulfillmentCost` standard) and posted COGS (journal) are shown as two labelled figures.                                                                                                                                                                                           | Adopted |
| D15-7  | **Agent-owned goods** follow the same physical path (reserve → transit → delivered) with `ownerAgentId` on every movement; never company inventory value or COGS. Agent ledger events are unchanged (dispatch fee at dispatch, earning per agreement event).                                                                                                                                                                                                                                                                                                                                                                                                                           | Adopted |
| D15-8  | **Failed delivery / cancellation in transit.** The reservation is never released while goods are physically out. DELIVERY_FAILED / return codes / cancelling a dispatched order leave the quantities in transit as RETURNING; "Receive returned goods" (physical receipt + inspection) transfers them back: saleable → origin warehouse (re-reserved if the order continues, otherwise released), damaged → damaged-goods warehouse. A reshipment from the carrier hub ships the in-transit quantity again without a new transfer.                                                                                                                                                     | Adopted |
| D15-9  | **Collection.** Cash is recognised only from a VERIFIED payment (Finance) — a salesperson's declaration is a claim, never a collection. Prepaid: receipt when verified (advance before delivery, allocated at invoice). COD: the carrier's confirmed collection posts Dr carrier-COD clearing / Cr AR (receivable from the carrier); the carrier's remittance settles clearing → bank (existing `PaymentSettlement`). Dispatch and delivery never post cash.                                                                                                                                                                                                                           | Adopted |
| D15-10 | **Returns after delivery.** From the order / invoice: "Return" creates a sales-return request (lines, quantities, reason) — no stock effect; "Receive & inspect" confirms it: saleable → stock, damaged → damaged-goods warehouse, credit note posted (revenue + COGS reversed at the invoice snapshot cost). RETURN_PENDING is resolved to returned / partially returned.                                                                                                                                                                                                                                                                                                             | Adopted |
| D15-11 | **Refunds.** A refund is a real money-out document (`CUSTOMER_REFUND`) recorded only when money is returned; refund due = collected − (net invoiced after credit notes) and is shown as "Refund pending" until recorded. Gateways are not integrated (ERP decision: no payment-gateway integration), so every refund is recorded manually with method + reference — the UI says so. A credit note alone never marks a refund done. Advances of undelivered / cancelled orders and overpayments can be refunded against the order.                                                                                                                                                      | Adopted |
| D15-12 | **Erroneous payment.** A verified payment recorded in error is reversed through an audited action (reason, `finance.payments.reverse`): status REVERSED, receipt reversed by a reversing entry — never deleted.                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Adopted |

## Agents, imports, partners, reports

| Id     | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | Status  |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------- |
| D15-13 | **Agent shipping agreement** becomes its own document under Agent → Settings: `AgentShippingAgreement` (number, agent, currency = agent currency, effective from/to, DRAFT / ACTIVE / INACTIVE) with explicit service rows (prepaid carrier, carrier COD, internal courier COD, internal courier prepaid) × destination (all destinations / country / city) → agreed charge. At most one ACTIVE agreement in force per agent per day (activation refuses overlaps; "replace from date" closes the previous one the day before). Existing tariff rows are migrated (ANY wildcards expanded, most specific wins). The commission agreement keeps the shipping _policy_ only. | Adopted |
| D15-14 | **Partner login** = a third user audience `PARTNER` (modelled on agent users): `User.companyPartnerId`, `partner.*` permissions only, deny-by-default except `@PartnerPortal` handlers, self-scoped endpoints. After the partnership ends the login keeps read-only access to historical statements until an administrator disables it; nothing is erased.                                                                                                                                                                                                                                                                                                                 | Adopted |
| D15-15 | **Partner statement per period:** payments are applied to closed periods oldest-first (derived, no stored allocation); the live estimate is labelled provisional; reviewed-but-not-closed periods are shown as "under review" without an approved amount.                                                                                                                                                                                                                                                                                                                                                                                                                  | Adopted |
| D15-16 | **Import permissions:** `crm.leads.import`, `store-orders.import` (company), `agent.leads.import`, `agent.orders.import` (agent); granted to nobody (company) / to existing agent ADMIN users (so they can delegate). `import-center.manage` stays the administrator catch-all. Records belong to the importer by default; an owner column is honoured only for users who may already assign (company: `crm.leads.manage` for leads, team/all scope for orders; agent: new `agent.records.assign`).                                                                                                                                                                        | Adopted |
| D15-17 | **Google Sheets** stay on the service-account connection (the user shares the private sheet with the OMS address as Viewer — never public). A spreadsheet is claimed by the first user/agent that connects it; others cannot import from it; sheets configured as continuous sync sources cannot be one-time imported (one ingestion path per sheet). Imported rows carry a row key (store orders: `creationIdempotencyKey`; leads: `importRowKey`) shared by both paths, so a retry or the other path never ingests the same row twice.                                                                                                                                   | Adopted |
| D15-18 | **Sales-report scope:** new `reports.sales.view_all` is the only key that opens company-wide sales reports / rankings (granted by migration only to current company-wide sales managers: `crm.leads.manage` holders who manage no team); team managers see their team; everyone else sees only their own figures and their own rank (position + count, no other names). `store-orders.view_all` and `crm.leads.manage` no longer widen reports. Agent side: new `agent.reports.view_team` (agent ADMIN preset) replaces `agent.records.view_all` as the team-report key.                                                                                                   | Adopted |
| D15-19 | **One order-entry form:** the company stepped form (`StoreOrderCreateDialog` steps) becomes a shared `OrderEntryFlow` driven by an adapter (company / agent); the agent portal page and company staff entering an agent order use it with the agent adapter (agent catalog, live quote/breakdown, declaration at create).                                                                                                                                                                                                                                                                                                                                                  | Adopted |
| D15-20 | **Data:** no wholesale reset. Open orders on Production are brought to the new model by an idempotent, dry-run-first backfill (reserve open orders; move shipped-not-delivered orders to transit); results recorded in `release.md`. The R14 recognition repair (D3-2) is applied under this brief's cleanup authority.                                                                                                                                                                                                                                                                                                                                                    | Adopted |
