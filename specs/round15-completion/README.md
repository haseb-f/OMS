## Rules for every stream

- Read `CLAUDE.md`, `.claude/OMS.md`, `.claude/guardians/{project-rules,erp-decisions,chief-accountant,ui-guardian}.md`
  and your spec before coding. Reuse existing services/components; no duplicate logic, no dead code, no TODO.
- Never `git stash`, never `git add -A`, **never commit** (the lead commits after review), never switch branches, never
  run `prisma generate` / `migrate` / `nest build` / `next build` (shared outputs), never edit files you do not own.
- Tests run against your own database: `DATABASE_URL=postgresql://oms:oms@localhost:5434/oms_r15_<stream>?schema=public`
  (already migrated). `pnpm --dir D:/Systems/OMS/apps/api exec jest <paths>`; web `pnpm --dir D:/Systems/OMS/apps/web exec vitest run <paths>`.
  Typecheck with `tsc --noEmit` and report only errors in your files (other streams are mid-edit).
- Nest wiring: put new controllers/services in your own module file; you may append ONE import line for that module to
  `agents.module.ts`, `store-orders.module.ts` or `app.module.ts` (append-only — never reorder or edit other lines).
  The same append-only rule applies to `navigation.config.ts` entries (W2 agent import item, W4 partners section).
- Every behaviour change has a test that fails without it (mutate the fix away once and say so).
- Keep `specs/round15-completion/progress-<stream>.md` current (what is done, verified how, what is open). It is the
  recovery point if the session is interrupted.
- Final report: changed files, tests run (command + result), open issues, anything the lead must integrate.
