# تسليم الجولة الخامسة — عمليات الطلبات، تسعير الوكلاء، مراجعة المدفوعات، التحسين البصري

التاريخ: 2026-10-01. الإصدار على الإنتاج: الدفعة 1 `5aa1c3b`، الدفعة 2 `5376d69`.

## 1. تعديل الطلبات وتحذيرات التكرار

**التعديل حتى التسليم:** من صفحة الطلب ← «تعديل الطلب». يعدّل الموظف العميل أو الأصناف أو الكميات أو الأسعار
أو العملة أو طريقة الدفع (مسبق/عند الاستلام) أو طريقة التنفيذ أو العنوان، ويكتب **سبباً إلزامياً**، ثم
«مراجعة الأثر» قبل الحفظ:

- **يمنع** (مع الخطوة المطلوبة): طلب مُسلَّم أو مُستلَم أو مرتجع أو ملغى؛ تغيير الأصناف أو العنوان بعد خروج
  الشحنة؛ تغيير العملة مع وجود دفعة مُرحّلة («اعكس أو استرد الدفعة … أولاً»)؛ فاتورة مُرحّلة (المسار: مرتجع
  مبيعات)؛ عمولة وكيل مُكتسبة أو مخزون وكيل مصروف.
- **يتطلب تأكيداً:** إعادة إصدار البوليصة إن كانت صادرة؛ إعادة تقييم الإبلاغات المعلّقة؛ دفعة زائدة تُحال
  للاسترداد؛ مراجعة المالية عند تغيير العملة مع إبلاغات معلّقة.
- لا تُعدَّل أي دفعة مُرحّلة أبداً (المبلغ والعملة والقيد كما هي)، ولا تُنشأ حركة مخزون.
- كل تعديل يُسجَّل (القيم القديمة/الجديدة، المنفّذ، الوقت، السبب) ويرفع رقم إصدار الطلب؛ إذا عدّل شخص آخر
  الطلب في الوقت نفسه يظهر «تم تغيير الطلب بواسطة … — أعد التحميل» ولا يُكتب فوق تعديله.
- وكيل المبيعات يعدّل طلباته فقط، ولا يمكنه التعديل بعد ترحيل دفعة أو فاتورة أو اكتساب عمولة.

**صفحة الطلب المختصرة:** شارتان منفصلتان (الدفع / التنفيذ)، وإجراء تالٍ واحد واضح، وبطاقة واحدة للعميل
والأصناف والإجماليات، والأقسام التفصيلية (المدفوعات، الشحنات، التعديلات والنشاط، التفاصيل الفنية) مطوية
وتتذكّر اختيار المستخدم.

**تحذير التكرار عند إنشاء طلب** (يدوي، تحويل عميل محتمل، طلب وكيل):

- **تطابق الهاتف** (بعد توحيد الصيغة، بغض النظر عمن أنشأ السجل): يظهر العميل وطلباته المتاحة (النشطة أولاً)
  وثلاثة خيارات: فتح الطلب الحالي / طلب جديد مقصود لنفس العميل / تصحيح البيانات. لا يُقبل الحفظ دون اختيار،
  ويُعاد استخدام العميل نفسه دون تكرار.
- **تطابق الاسم فقط** (مع توحيد الحروف العربية: أ/ا، ي/ى، ة/ه…): تنبيه أخف — «نفس العميل» أو «عميل مختلف
  باسم مشابه». لا دمج تلقائي بالاسم أبداً.
- **خارج النطاق** (عميل وكيل آخر، أو عميل شركة يراه وكيل، أو عميل وكيل يراه موظف الشركة): لا تظهر أي تفاصيل؛
  يُنشأ الطلب ويُعلَّم «مراجعة تكرار» يحسمها موظف داخلي مخوَّل من فلتر «مراجعة التكرار» في قائمة الطلبات.
- النقر المزدوج أو إعادة الإرسال لا ينشئ طلباً ثانياً.

## 2. ربط المنتجات بالوكلاء

- من محرر المنتج: «الملكية: الشركة / وكيل» ثم اختيار الوكيل، و«نوع البند: منتج / خدمة» مستقل عن تتبع المخزون.
- أو من صفحة الوكيل ← تبويب «المنتجات»: ربط منتج موجود، أو منتج جديد للوكيل، أو فك الربط (يُرفض إن كان المنتج
  مستخدماً في حركات أو طلبات)، مع نسبة العمولة الموروثة أو الاستثناء لكل صنف. يتطلب الربط صلاحيتي الوكلاء
  والمنتجات.
- موظف الوكيل يرى تلقائياً منتجات وكيله النشطة القابلة للبيع فقط عند إنشاء الطلب (مقيّدة من الخادم).

## 3. متى يصبح سعر الشحن نهائياً

ثلاثة مبالغ منفصلة: (1) شحن العميل، (2) رسم الشحن التعاقدي على الوكيل، (3) التكلفة الفعلية لشركة الشحن (داخلية).

تعرفة الوكيل في الاتفاقية حسب **قناة التوصيل × طريقة الدفع × الوجهة** (الأكثر تحديداً يفوز: المدينة ثم القناة ثم
طريقة الدفع). مثال الاتفاقية: مسبق × شركة شحن 25 · عند الاستلام × شركة شحن 35 · عند الاستلام × مندوب داخلي 25.

- عند إدخال الطلب: إن تساوت كل القنوات للوجهة وطريقة الدفع **يُثبَّت فوراً**؛ وإلا يظهر «تقديري — يصبح نهائياً
  عندما يختار قسم الشحن طريقة التوصيل».
- **يصبح نهائياً لحظة اختيار قسم الشحن لشركة الشحن** (خارجية = شركة شحن، داخلية = مندوب). إن لم تكن هناك تعرفة
  للتركيبة (مثل مسبق × مندوب داخلي) يُرفض الإسناد مع ذكر التركيبة. لا يُشحن طلب وكيل وسعره معلّق، ولا تُكتسب
  العمولة قبل تثبيته، ولا يتغير بعد الاكتساب أو بتعديل التعرفة لاحقاً.
- **شامل الشحن:** إجمالي العميل المتفق عليه ثابت؛ مثال 500 مع رسم 35 ← بضاعة 465 + شحن 35.
- **الشحن مضاف:** البضاعة تُعرض منفصلة؛ مثال بضاعة 400 وتقدير 25 (المستحق 425) ← ثُبّت 35 ← المستحق 435 ويتطلب
  «تأكيد موافقة العميل»؛ إن كان العميل دفع 425 يظهر المتبقي 10. لا زيادة صامتة على العميل.
- لا خصم مزدوج: شحن العميل المحصّل يسوّي رسم الوكيل التعاقدي. هامش الشركة = الرسم التعاقدي − التكلفة الفعلية
  (25 − 20 = 5)، داخلي فقط. استيراد فواتير شركات الشحن يحدّث التكلفة والهامش ولا يُنشئ أي خصم على الوكيل.

## 4. ما يراه الوكيل مقابل الموظفين الداخليين

- **الوكيل:** منتجاته، أسعار البيع المتفق عليها، شحن العميل، الرسم التعاقدي ومصدره (تقديري/نهائي)، العمولة
  وكشف الحساب. **لا يرى** تكلفة شركة الشحن ولا الهامش في أي شاشة أو API أو تصدير أو طباعة أو رسالة خطأ (تم
  إغلاق تسرّب سابق في تقرير العمولات، وفحص آلي يمنع عودته).
- **الداخلي:** كل ما سبق + التكلفة الفعلية والهامش في «تسعير الشحن» وربحية الطلب وتقارير الوكلاء الداخلية.

## 5. كيف تطابق المالية المدفوعات وتؤكدها

«مراجعة المدفوعات» أصبحت مساحة عمل بمراحل واضحة (عدد ومبلغ لكل مرحلة): إبلاغات بانتظار المراجعة ← حركات كشف غير
مطابقة ← استثناءات ← بانتظار التأكيد ← مخصصة جزئياً ← بانتظار التسوية. المصطلحات موحّدة في كل الشاشات:
**مُبلغ عنه** · **مطابق غير مُرحّل** · **مؤكد ومُرحّل** · **مُسوّى للبنك**.

- لوحة المطابقة الجانبية: الإبلاغ مقابل حركة الكشف (المبلغ، العملة، التواريخ، المرجع، الطريقة، الأدلة، الفروق)
  وجملة الأثر المحاسبي الدقيقة قبل التنفيذ.
- أزرار دلالية: تأكيد وترحيل (أخضر)، رفض الإبلاغ (أحمر هادئ مع سبب)، مطابقة (لون أساسي)، إلغاء المطابقة / عكس
  الترحيل (ثانوي، ويذكر القيد المعكوس). «رفض الإبلاغ» ≠ «استرداد للعميل».
- إجراءات جماعية بنتيجة لكل عنصر؛ القبول الجماعي للاقتراحات يتطلب تطابق مرجع أو رقم طلب وحالة نجاح معروفة.
- قواعد الترحيل والصلاحيات والعملة ومنع التكرار والتسوية لم تتغير.
